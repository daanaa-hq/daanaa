## Overview

Daanaa is building infrastructure for nonprofit discovery. We're a 501(c)(3)-focused startup backed by EcoMargins Consulting, and we're launching publicly Aug 15, 2026.

**Your role:** Build the first phase of the platform—a searchable directory of 1.87M nonprofits with evidence-based financial context and AI-assisted agents for operations.

This is not a traditional SaaS role. We're building with **intentional governance** (11 Stewardship principles), **local-first architecture** (home server + droplet), and **minimal AI** (only where it genuinely helps fairness). You'll work directly with the founder, make architectural decisions, and see your work launch to thousands of users in the first 8 weeks.

---

## What You'll Build (Aug 1–15)

**Sprint 1: Public soft launch**

- FastAPI backend (6 API endpoints: search, detail, claims, wallet)
- React frontend (4 pages: search, nonprofit detail, wallet, claim form)
- Elasticsearch search index (1M+ nonprofits)
- Nonprofit Onboarding Agent (validates claims, auto-approves/flags)
- Integration tests + end-to-end tests
- 50-nonprofit sandbox testing + feedback collection

**Success criteria:** Launch Aug 15 with 1K+ searchable orgs, 50+ test nonprofits claiming profiles, zero critical bugs.

---

## What You'll Build (Aug 15 – Sep 1)

**Phase 2: Volunteer signals + all agents**

- Volunteer interest tracking (donor signals "looking for volunteer opportunity")
- Nonprofit admin dashboard (see interested volunteers, filter by skills)
- Support Triage Agent (classify + draft responses to support emails)
- Database migrations (zero data loss)
- Testing infrastructure for Phase 3

---

## What You'll Build (Sep 1 – Nov 15)

**Phase 3 + stabilization**

- Volunteer messaging (nonprofit → volunteer direct contact)
- Performance tuning (99.9% uptime, <500ms search)
- Security baseline (HTTPS, rate limiting, input validation)
- Handoff to future team (docs, runbooks, architecture guide)

## The Catch

⚠️ **High velocity.** 15 days to launch is not fast—it's *very* fast. You'll need to make decisions quickly, cut scope ruthlessly, and trust that iteration continues post-launch.

⚠️ **Ambiguity.** Some design details are intentionally left open (you fill them in). Some requirements will change as you learn the problem. This is by design, but it requires adaptability.

⚠️ **Principles-first.** If you propose an optimization that violates STEWARDSHIP principles, you'll be asked to find another way. This is a feature, not a bug—but it's different from typical startups.

⚠️ **Async infrastructure.** We run on home server + droplet. Not AWS/GCP. You'll debug in a more constrained environment, which can be educational or frustrating depending on your temperament.
