# Donation CTA Removal — Phase 1 Diagnosis (2026-06-10)

**Directive:** On legal counsel's advice, public surfaces must never show donation links or
donation CTAs. Primary yellow CTA → official website, fallback social. Donation data retained
internally for the claim flow. No data destruction.

**Stack note:** Task prompt said "FastAPI + DuckDB"; actual stack is **Flask + SQLite**
(`daanaa_api.py`, `data/merit_registry.db`) plus a **static precompute droplet**
(`scripts/droplet_api.py` + per-org JSON files generated by `scripts/precompute_*.py`).
Routes named in the prompt (`api/search-fast`, `api/organizations-fast`, `api/nonprofits`,
`api/directory`, `api/categories`) do not exist; the real route inventory is below.

---

## A. Key architecture facts

1. **Website fields that exist** (DB `registry_enriched` + API): `website`, `website_status`
   (`ok` = verified live & on-domain, `beta` = discovered/unconfirmed), `website_final_domain`,
   `website_checked_at`. Frontend also gets `has_website` and `data_badges.website`.
2. **Social link fields: NONE exist** — not in the DB, not in any API response, not in frontend
   types. The website→social fallback chain **cannot be populated today**; the helper should be
   built with the social branch present but it will always return null until social data exists
   (e.g., collected during claiming). Practical fallback today: website → none (or ProPublica
   EIN record, which the detail page already uses — decision needed whether that neutral
   "View public record" link survives as the no-website state).
3. **Provenance:** No formal "Public Record" vs "Daanaa Added" sections. Provenance is conveyed
   via `AiBadge` ("Generated by AI from public records"), a "⚠️ discovered" chip for
   `website_status='beta'`, and `data_badges` (`website`/`donate`: `beta|provider|claimed`).
   Non-IRS-sourced links already get the "not confirmed by the organization" treatment.
4. **Yellow CTA style (reuse as-is):**
   `inline-flex items-center gap-2 font-body text-[15px] font-semibold bg-soft-gold
   text-deep-navy px-7 py-3 rounded-full hover:bg-bright-gold transition-colors`
   The `website_status==='ok'` branch at `OrganizationDetail.tsx:704-723` is already nearly the
   desired end-state pattern.
5. **Fail-closed donate gate** (`_donate_eligible_basic`, `daanaa_api.py:1129`; nulling at
   846-909): keep — it protects the claim/admin path too.
