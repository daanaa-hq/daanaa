# Enrichment Pipeline Runbook

Operational guide for running the nonprofit discovery enrichment pipeline (semantic lookup + AI inference + quality measurement + autonomous prompt improvement).

**Status:** All scripts functional as of Task 9. Cron jobs created but NOT YET installed in production crontab (manual step required — see section 3).

---

## 1. Quick Start

### Dry-Run (Safe — No Database Writes)

Test the enrichment pipeline on a subset of organizations without modifying the database:

```bash
cd /home/akbar/meritgiving

# Default: 10,000 orgs with 4 workers
bash scripts/run_enrichment_dryrun.sh

# Custom: 100 orgs (fast test)
bash scripts/run_enrichment_dryrun.sh 100

# Custom: 5,000 orgs with 2 workers
bash scripts/run_enrichment_dryrun.sh 5000 2
```

**Output:** JSON stats printed to stdout, including orgs processed, tags generated, websites generated, and elapsed time.

**Example output:**
```json
{
  "run_date": "2026-07-06",
  "elapsed_seconds": 30.01,
  "orgs_processed": 100,
  "tags_generated": 50,
  "websites_generated": 50,
  "dry_run": true
}
```

### Full Batch Run (Database Write)

Enrich organizations and write results to `enrichment_run` table:

```bash
cd /home/akbar/meritgiving
source venv/bin/activate

# Enrich up to 1,000 orgs with 4 workers
python3 scripts/enrich_batch.py --workers 4

# Enrich all missing-enrichment orgs with custom batch size
python3 scripts/enrich_batch.py --batch-size 50

# Enrich only 500 orgs (for testing)
python3 scripts/enrich_batch.py --max-orgs 500
```

**Key flags:**
- `--dry-run` — Process orgs but do not write to DB
- `--max-orgs N` — Limit to N organizations
- `--workers N` — Number of parallel workers (default: 1)
- `--batch-size N` — Orgs per inference batch (default: 20)

### Check Batch Health

Monitor the success/health of recent enrichment runs:

```bash
cd /home/akbar/meritgiving

python3 scripts/monitor_batch.py

# Check a specific date

```

**Example output:**

```

Or (when batch ran successfully):
```

## 2. Automated Cron Jobs

Three cron jobs work together to enrich, measure quality, and improve prompts:

| Time | Job | Script | Purpose |
|------|-----|--------|---------|
| **8:00 PM** | Nightly enrichment | `scripts/cron_enrich_nightly.sh` | Generate cause tags + websites for ~1000 orgs |
| **6:00 AM** | Quality measurement | `scripts/measure_quality_cron.py` | Measure accuracy/validity of previous day's run |
| **7:00 AM** | Prompt improvement | `scripts/improve_prompts_cron.py` | Auto-generate improved prompts if quality < target |

### Manual Installation (One-Time Setup)

**⚠️ IMPORTANT:** These cron jobs are NOT automatically installed. You must manually add them to your crontab:

```bash
crontab -e
```

Then paste the following (adjust times/paths as needed):

```cron
# Enrichment nightly batch (8 PM)
0 20 * * * cd /home/akbar/meritgiving && /home/akbar/meritgiving/scripts/cron_enrich_nightly.sh >> /home/akbar/meritgiving/logs/enrich_batch_$(date +'%Y%m%d').log 2>&1

# Quality measurement (6 AM)
0 6 * * * cd /home/akbar/meritgiving && /home/akbar/meritgiving/venv/bin/python3 scripts/measure_quality_cron.py >> /home/akbar/meritgiving/logs/quality_cron_$(date +'%Y%m%d').log 2>&1

# Prompt improvement (7 AM)
0 7 * * * cd /home/akbar/meritgiving && /home/akbar/meritgiving/venv/bin/python3 scripts/improve_prompts_cron.py >> /home/akbar/meritgiving/logs/improve_prompts_cron_$(date +'%Y%m%d').log 2>&1
```

To verify cron jobs are installed:
```bash
crontab -l | grep enrich
```

## 4. Database Schema

### enrichment_run Table

Stores every enrichment result (cause tags and/or website suggestions) generated by the pipeline.

| Column | Type | Description |
|--------|------|-------------|
| `run_id` | INTEGER | Primary key (auto-increment) |
| `run_date` | DATE | Date enrichment was generated (YYYY-MM-DD) |
| `org_ein` | TEXT | Organization EIN (unique per run) |
| `enrichment_type` | TEXT | 'cause_tags' or 'website' |
| `generated_value` | TEXT | The generated tags or domain name |
| `confidence_score` | REAL | 0.0–1.0; currently hardcoded to 0.7 (will be AI-computed in future versions) |
| `context_used` | TEXT | JSON object with metadata: `{similar_count: 5, semantic_similarity: 0.85, ...}` |
| `prompt_version` | TEXT | Which prompt template was used (e.g., 'v1.0', 'v1.1') |
| `created_at` | TIMESTAMP | When record was inserted |

**Indexes:**
- `idx_enrichment_date_ein` on `(run_date, org_ein)` — for fast lookups by date and org

**Constraints:**
- `UNIQUE(run_date, org_ein, enrichment_type)` — prevent duplicate enrichments for same org/date

### quality_log Table

Stores daily quality metrics (accuracy, validity trends) used to decide whether to improve prompts.

| Column | Type | Description |
|--------|------|-------------|
| `id` | INTEGER | Primary key (auto-increment) |
| `date` | DATE | Date these metrics were measured (YYYY-MM-DD) |
| `metric_type` | TEXT | 'cause_tag_accuracy' or 'website_validity' |
| `value` | REAL | 0.0–1.0; the measured accuracy/validity for this day |
| `cohort` | TEXT | Cohort measured: 'All', 'NTEE_A', 'NTEE_B', 'size_micro', 'size_professional', 'size_established' |
| `prompt_version` | TEXT | Which prompt version this metric was computed from |
| `notes` | TEXT | Optional human-readable notes (e.g., "Below target, improvement triggered") |
| `created_at` | TIMESTAMP | When record was inserted |

**Indexes:**
- `idx_quality_date_metric` on `(date, metric_type, cohort)` — for fast trend queries

**Constraints:**
- `UNIQUE(date, metric_type, cohort, prompt_version)` — prevent duplicate metrics for same day/metric/cohort

## 5. Configuration

All enrichment parameters are defined in `scripts/enrich_batch_config.json`:

```json
{
  "version": "1.0",
  "batch": {
    "max_workers": 6,
    "batch_size_per_inference": 20,
    "timeout_seconds": 300
  },
  "servers": {
    "qwen_port": 11437,
    "embeddings_port": 11436
  },
  "thresholds": {
    "cause_tags_min_confidence": 0.65,
    "quality_regression_alert": 0.10,
    "accuracy_target": 0.75,
    "validity_target": 0.80
  },
  "prompts": {
    "v1.0": {
      "cause_tags": "Similar high-performing orgs are tagged with: {similar_tags}. ...",
      "website": "Similar organizations in {city}, {state} use domains like: ..."
    },
    "v1.1": {
      "cause_tags": "Similar high-performing orgs in {ntee} are tagged with: ...",
      "website": "Similar organizations in {city}, {state} use domains like: ..."
    }
  },
  "cohorts": [
    {"id": "All", "filter": ""},
    {"id": "NTEE_A", "filter": "ntee1 = 'A'"},
    {"id": "NTEE_B", "filter": "ntee1 = 'B'"},
    {"id": "size_micro", "filter": "total_revenue < 150000"},
    {"id": "size_professional", "filter": "total_revenue BETWEEN 150000 AND 700000"},
    {"id": "size_established", "filter": "total_revenue > 700000"}
  ]
}
```

### Key Parameters

- **accuracy_target**: 0.75 (75%) — if daily accuracy falls below this, `improve_prompts_cron.py` will generate a new prompt version
- **validity_target**: 0.80 (80%) — threshold for website validity
- **cause_tags_min_confidence**: 0.65 — minimum confidence threshold for writing a cause-tag enrichment (currently unused, but available for filtering)
- **qwen_port** / **embeddings_port**: Ports where llama-server instances run (see section 6)

### Prompt Versions

New prompt versions are automatically saved when prompt improvement is triggered (by `improve_prompts_cron.py`). Version history is stored in:

```
data/enrichment/prompt_versions.json
```

**Note:** This file should NOT exist until the first improvement run. If it exists in production and you haven't manually triggered improvements, it may indicate a dry-run or test that modified production paths — investigate.

## 6. Infrastructure Requirements

The enrichment pipeline requires two local inference services (NOT cloud APIs):

### Qwen2.5-32B Language Model (Port 11437)

Generates cause tags and website suggestions.

**Start the server:**
```bash
llama-server -m /path/to/Qwen2.5-32B-Instruct-Q4_K_M.gguf \
  --port 11437 \
  --ngl 99 \
  --main-gpu 0 \
  --ctx-size 8192
```

**Health check:**
```bash
curl http://localhost:11437/health 2>&1 | jq .
```

### mxbai-embed-large Embeddings Model (Port 11436)

Generates 1024-dimensional embeddings for semantic similarity lookups.

**Start the server:**
```bash
llama-server -m /path/to/mxbai-embed-large.Q6_K.gguf \
  --port 11436 \
  --embedding \
  --ngl 99 \
  --main-gpu 0
```

**Health check:**
```bash
curl -X POST http://localhost:11436/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{"input": "test"}' 2>&1 | jq .
```

### Example 3: Check Enrichment Results

Query the database to see what was generated:

```bash
sqlite3 data/merit_registry.db
```

```sql
-- Count enrichments by type for today
SELECT enrichment_type, COUNT(*) 
FROM enrichment_run 
WHERE run_date = '2026-07-06'
GROUP BY enrichment_type;

-- View recent cause tags
SELECT org_ein, generated_value, confidence_score
FROM enrichment_run
WHERE enrichment_type = 'cause_tags' AND run_date = '2026-07-06'
LIMIT 10;

-- View quality metrics trend (past 7 days)
SELECT date, metric_type, value, prompt_version
FROM quality_log
WHERE metric_type = 'cause_tag_accuracy'
ORDER BY date DESC
LIMIT 7;
```
