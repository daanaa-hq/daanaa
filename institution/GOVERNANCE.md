# Governance

## Document Control

| Field | Value |
|---|---|
| Purpose | Define decision tiers, approval gates, founder requests, and board-simulation expectations. |
| Responsible role | Chief Steward; Stewardship Systems Agent maintains records. |
| Authority level | Governance operating model; protected by `CONSTITUTION.md`. |
| Review trigger | Major product/revenue/data change, incident, recurring confusion, or founder delegation change. |
| Editable status | Editable by ordinary agents for proposed process improvements; approval gates are protected. |
| Dependencies | `CONSTITUTION.md`, `FOUNDER_REQUESTS.md`, `DECISION_LOG.md`. |
| Retirement condition | Retire when superseded by a legally authorized governance charter. |

## Decision Tiers

- Routine: reversible documentation, tests, audits, and isolated operational records. Agents may act.
- Operational: product or script changes with limited blast radius. Agents may propose and implement only when tests pass and no approval gate is crossed.
- Material: public claims, privacy, security, money, user data, methodology, or automation autonomy. Requires decision record and founder approval when authority is not clearly delegated.
- Constitutional: mission, protected rules, public scoring principles, data rights, or regulated activity. Requires founder approval and constitutional review.

## Approval Gates

Explicit founder approval is required for production deployment, database migration, destructive commands, deleting material data, auth/authz changes, external communications, publishing content, spending money, activating paid services, submitting applications, signing terms, changing public scoring or peer methodology, handling private nonprofit financial data, modifying protected principles, and launching regulated financial features.

## Founder Requests

Do not interrupt for routine matters. Record requests in `FOUNDER_REQUESTS.md` with recommended default, alternatives, impact, delay risk, time needed, deadline, and whether safe work can continue.
