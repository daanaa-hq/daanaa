# Continuous Improvement

## Document Control

| Field | Value |
|---|---|
| Purpose | Define retrospectives, simplification checks, and workflow improvement rules. |
| Responsible role | Stewardship Systems Agent. |
| Authority level | Operating practice; not constitutional rule. |
| Review trigger | Meaningful completed task, repeated failure, incident, or weekly review. |
| Editable status | Editable by ordinary agents with evidence. |
| Dependencies | `LESSONS.md`, `DECISION_LOG.md`, `RISK_REGISTER.md`, `HYPOTHESES.md`. |
| Retirement condition | Retire when replaced by a measured continuous-improvement workflow. |

## Completion Reflection

For meaningful tasks, ask:

- Could it be simpler, safer, cheaper, faster, or more understandable?
- Could it be automated after manual validation?
- Could it be reused by nonprofits?
- Could it reduce founder dependence?
- Could it improve nonprofit life?
- Could it better reflect stewardship?

## Repeated Failure Rule

When the same failure occurs twice, conduct a retrospective and improve the relevant instruction, test, skill, workflow, or documentation. Do not rely on memory or discipline when a structural guard is needed.
